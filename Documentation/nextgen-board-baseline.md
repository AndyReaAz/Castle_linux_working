# NextGen Linux board baseline

`build-fast.sh` now finds its default board seed in
`arch/arm/configs/nextgen_defconfig`. No external 6.6 config or workstation
path is required. `KERNEL_BASE_CONFIG` remains an explicit diagnostic override.

The frozen defconfig is generated by applying the existing normal-profile
wrapper to that uploaded seed, then running ARM Kconfig `savedefconfig`.
This preserves the board's configured drivers and adds the already-established
common RO requirements: SquashFS/LZO and four loop devices. It is not a generic
SAMA5 replacement, and no feature-pruning or driver policy change is included.

## Validation

Using ARM GCC 13.3.0, the same compiler version named in the supplied config:

1. Apply `build-fast.sh config normal` to the full uploaded seed and to the
   repository defconfig in separate output directories. All expanded CONFIG
   values match (`scripts/diffconfig` produces no output).
2. Repeat for `build-fast.sh config bringup`. All expanded CONFIG values match.
3. Both paths pass the wrapper's required-symbol and kernel-release checks.

Compiler/host probes are regenerated by Kconfig rather than committed as
policy. Normalisation of the original full seed on the validation host changed
only PAHOLE_VERSION and the derived CC_CAN_LINK probe before the profile
settings were applied. Both sides of each comparison use the same host.

This import does not change C sources, the device tree or the wrapper. The
user's just-built normal and bringup artifacts need not be discarded solely
because the seed is now in Git. These are build/configuration results, not
hardware boot or acquisition validation.

## Local incremental builds

```sh
unset KERNEL_BASE_CONFIG
./build-fast.sh build normal
./build-fast.sh build bringup
```

Keep normal and bringup module trees separate even though their release
strings match. Normal has SPI-NOR as a module and no framebuffer console;
bringup has built-in SPI-NOR and the operator framebuffer console. Heavyweight
CI remains manually dispatched, so this seed import does not launch a cold
kernel build.
